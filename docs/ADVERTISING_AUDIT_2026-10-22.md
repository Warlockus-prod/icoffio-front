# Аудит рекламы icoffio — 22 октября 2026

## Область и результат

Основные адреса, подтверждённые владельцем: `https://icoffio.com` и
`https://app.icoffio.com`. Проверены EN/PL, desktop/mobile, прямое открытие
статьи, переход из главной, сохранённое согласие, согласие через интерфейс,
отзыв согласия и новый браузер с отказом. Кампании, ставки, бюджеты и статусы
в рекламном кабинете не менялись.

**Две разные проблемы:** ошибки жизненного цикла интеграции в коде сайта и
отсутствие креативов в ответах поставщика. Исправление первой не доказывает
восстановления оплачиваемых показов. Завершить проверку заполнения можно только
с действующей кампанией/тестовым креативом нужного формата.

## Найденные ошибки сайта и исправления 10.23.5

1. **Наблюдатель не запускался после первого согласия.** При асинхронной загрузке
   SDK React effect видел `scriptLoaded=false` и завершался. `onload` менял ref,
   но не запускал effect снова. Поздно появившиеся контейнеры после фиксированных
   ретраев пропускались. Новый `lib/vox-ad-lifecycle.ts` устанавливает наблюдение
   до загрузки SDK, использует его очередь и очищает устаревшие callbacks.
2. **InImage считался готовым для всего пути слишком рано.** Один флаг pathname
   не учитывал изображения, появившиеся позже. Теперь регистрируются реальные
   изображения hero/текста статьи, по одному разу на DOM-узел и экземпляр SDK.
   Миниатюры и рекламные картинки исключены. `image`/`imageSelector` проверены
   на реальном модуле VOX; стандартные ограничения размеров SDK сохранены.
3. **Display мог измерить tracking iframe вместо баннера.** Первый iframe 1×1
   приводил к скрытию всего контейнера. Теперь выбирается реальный креатив среди
   дочерних элементов/media. Статус no-fill обновляется по атрибуту SDK и виден
   диагностике как `empty`, вместо вечного `loading`.
4. **Видео нарушало жизненный цикл согласия и просмотра.** Запросы теперь требуют
   рекламного согласия; отзыв останавливает загрузку/воспроизведение. Impression
   и start отправляются при фактическом воспроизведении один раз. Исправлены
   квартильные события, ложный complete после skip и повторное воспроизведение
   одного аукциона с теми же tracking URL.
5. **Ошибки VAST маскировались под no-fill.** API различает `no_fill`,
   `upstream_timeout`, `client_aborted`, `invalid_vast`, `missing_media`,
   `unsupported_wrapper` и upstream HTTP/network errors. Перенаправления
   заблокированы, чтобы публичный resolver не обходил allowlist DSP-доменов.
   Цепочки VAST Wrapper пока не поддерживаются; это явно диагностируется.

Основные файлы: `components/AdManager.tsx`, `lib/vox-ad-lifecycle.ts`,
`components/UniversalAd.tsx`, `components/VideoPlayer.tsx`,
`app/api/video/preroll/route.ts`, статья и `scripts/live-ad-debug.js`.

## Что остаётся на стороне поставщика

- Нужна активная отдача для InImage и отдельных Display PlaceID из
  `lib/config/adPlacements.ts`. Кампания только InImage не заполняет Display
  автоматически. Проверить формат/размер, статус и модерацию креатива,
  даты, остаток/лимиты, SSP/placement, разрешённые домены, географию, частоту и
  требования к consent. **Конкретный ограничитель в кабинете пока не установлен.**
- Для видео нужен действующий тег с Inline VAST и воспроизводимым медиафайлом
  либо согласованная доработка поддержки Wrapper. Пустой VAST не содержит видео,
  которое сайт мог бы воспроизвести.
- Доступное v3 API возвращало пустые списки кампаний у найденных тестовых
  рекламодателей. Это API может не индексировать Console-created кампании,
  поэтому пустой список не доказывает отсутствие кампаний вообще. Полный
  Console `/core` вернул 401: сохранённая сессия истекла. Нужны актуальный
  доступ/ID кампании для проверки точной причины no-fill. Секреты не копировались.
- DNS `ssp.hybrid.ai` из контейнера в одном замере не разрешился, повторный
  успешный lookup занял 56 мс. Это дополнительное наблюдение, а не доказанная
  причина всех таймаутов; после успешного соединения VAST тоже бывал пустым.
- Нужен официальный `ads.txt` от VOX/других уполномоченных продавцов с настоящими
  seller/account ID. Файл отсутствует на обоих адресах. По
  [спецификации IAB Tech Lab](https://iabtechlab.com/ads-txt/) он публикует
  авторизацию продавцов инвентаря; отсутствие может ограничивать спрос у
  покупателей, проверяющих авторизацию. Причинная связь с конкретным no-fill
  пока не доказана. Выдуманные seller ID и скопированные чужие записи не добавлялись.

Запрошены ID действующих кампаний/тестовых креативов или актуальный VAST-тег.
Новые оплачиваемые кампании и бюджеты без конкретных параметров не создавались.

## Отдельный тестовый web.icoffio.com

На нём настроен Bidio/Prebid, а `CMP_PROVIDER='none'` и `CMP_ID=''`.
Браузер показывает `TCF2 CMP not found. Canceling auction`. Есть также
дополнительные CSP-блокировки ресурсов этой тестовой интеграции. Это отдельная
проблема тестового хоста, не причина 204 основного VOX-стека. По уточнению владельца
переключение/доработка тестового Bidio в этот ремонт не включены.

Документация Prebid подтверждает зависимость TCF-модуля от доступной CMP:
[TCF Consent Management Module](https://docs.prebid.org/dev-docs/modules/consentManagementTcf.html).
Собственный localStorage-баннер не создаёт IAB TCF signal. Подмена согласия
или фиктивные события показов не применялись.
